# 2026-05-07

## RegVFS 注册表插件 Bug 修复 (v3.0.0 → v3.1.0)

修复三个问题：

### Bug 1: 双击文件夹弹出"没有打开该链接的应用"
- **根因**: 缺少 `VFS_ContextVerbW` 导出函数。Opus 双击目录时调用此函数，找不到就将 reg:// URL 当作 shell 链接处理
- **修复**: 新增 `VFS_ContextVerbW` 实现，当 `lpszVerb==NULL`（双击）且 `dwFlags & DOPUSCVF_ISDIR` 时返回 `VFSCVRES_CHANGEDIR`，在 `lpszNewPath` 中填入目标路径

### Bug 2: 后退按钮直接跳到根目录桌面
- **根因**: `VFS_ReadDirectoryW` 中 `VFSREAD_BACK`/`VFSREAD_FORWARD`/`VFSREAD_PARENT`/`VFSREAD_ROOT` 的处理被合并到 FREEDIR 分支中直接返回 TRUE，未显式处理。Opus 使用内部导航历史管理 back/forward，但需要插件对这些操作码正确响应
- **修复**: 将 `VFSREAD_BACK`/`VFSREAD_FORWARD`/`VFSREAD_PARENT`/`VFSREAD_ROOT` 单独处理，返回 TRUE 让 Opus 用内部历史栈和 `VFS_GetPathParentRootW` 处理路径导航

### Bug 3: 地址栏显示网络图标
- **根因**: `VFSPROP_GETFOLDERICON` 属性返回 FALSE，Opus 无自定义图标信息就使用默认网络图标
- **修复**: `VFSPROP_GETFOLDERICON` 返回 TRUE（让 Opus 使用 `VFS_IdentifyW` 中设置的 regedit.exe 图标）；新增 `VFS_GetFileIconW` 为不同项目类型提供图标（注册表键用 regedit.exe 图标，注册表值用 shell32.dll 图标）

### 新增文件
- `.def` 文件新增 `VFS_ContextVerbW` 和 `VFS_GetFileIconW` 导出
- 新增 `IsRegKeyPath()` 辅助函数判断路径是否为注册表键

### 编译
- DLL 编译成功，28 个导出函数全部验证通过

## RegVFS 二次审查修复

代码审查发现并修复 4 个问题：

1. **P0 - VFS_PropGetW VFSPROP_GETFOLDERICON 多余操作**: 原代码先 ExtractIconExW 获取图标再 DestroyIcon 销毁，纯属浪费。简化为直接设置 `*lpPropData = TRUE` 返回
2. **P0 - VFS_GetFileIconW 文件图标错误**: 对注册表值（文件）使用 `shell32.dll` 图标索引 0（文件夹图标），改为索引 2（文档图标）
3. **P1 - VFS_IdentifyW 图标未初始化**: ExtractIconExW 失败时 hIconSmall/hIconLarge 保持未初始化值，修复为先初始化为 NULL
4. **P1 - VFS_DeleteFileW 签名不匹配**: 缺少 `dwFlags` 和 `iSecurePasses` 参数，与 SDK 原型不一致，导致调用时栈不平衡。已补齐参数

## RegVFS 崩溃修复 (v3.2.0)

二次审查后的修改导致打开 reg:// 直接崩溃。对比 RcloneVFS（正常工作的插件）找到根因：

### 崩溃根因分析
1. **VFSPROP_GETFOLDERICON 返回 TRUE 导致崩溃**: RcloneVFS 对此属性返回 FALSE。返回 TRUE 后 Opus 可能期望从 lpPropData 指向的结构获取图标数据，而我们的实现只是往里面写了个 BOOL 值，导致 Opus 读取无效内存
2. **VFS_GetFileIconW 实现存在风险**: IsRegKeyPath 对每个项目做 RegOpenKeyExW，路径格式不匹配时可能导致异常；且此函数在 RcloneVFS 中完全不存在

### 修复措施
1. **VFSPROP_GETFOLDERICON**: 改回返回 FALSE（与 RcloneVFS 一致），Opus 会使用 VFS_IdentifyW 中的 regedit.exe 图标作为 VFS 命名空间图标
2. **移除 VFS_GetFileIconW**: 从源码和 .def 中完全删除，Opus 使用默认 shell 图标
3. **移除 IsRegKeyPath()**: 辅助函数不再使用，已删除
4. **VFS_ReadDirectoryW 导航操作码**: 回退到 RcloneVFS 策略，VFSREAD_BACK/FORWARD/PARENT/ROOT 不再显式处理，走默认的 ERROR_NO_MORE_FILES 返回

### 保留的修复
- VFS_ContextVerbW（Bug 1 双击修复）✓
- VFS_DeleteFileW 签名修正（5 参数匹配 SDK）✓
- VFS_IdentifyW 图标 NULL 初始化 ✓

### 经验教训
**VFS 插件开发的铁律：参照已知可工作的插件（RcloneVFS）实现，不要猜测 SDK 行为**。
VFSPROP_GETFOLDERICON 返回 FALSE 意味着"我不提供自定义文件夹图标"，Opus 自动回退到 VFS_IdentifyW 的 hIconSmall/hIconLarge 作为整个 VFS 的图标。
VFS_GetFileIconW 是可选导出，不实现时 Opus 使用默认 shell 图标，更安全。
