## 一、改造目标

### 1.1 核心改动

| 改动项 | 改造前 | 改造后 |
|-------|-------|-------|
| 根目录 | 显示 7 个导航目录 | 直接显示我的仓库列表 |
| 功能入口 | 路径导航目录 | 右键菜单 + `?view=` 参数 |
| 仓库虚拟入口 | 目录中混合显示 | 右键菜单 + `?view=` 参数 |
| owner 显示 | `owner/repo/` 两级路径 | `repo/` + `?owner=` 参数消歧 |
| 分页 | `page:N` 路径段 | `?page=N` 查询参数 |
| 分支切换 | `@{ref}` 路径段 | `?ref=` 查询参数 |

### 1.2 设计原则

1. **路径 = 位置**：路径只表示文件位置，不承载视图/动作
2. **参数 = 查询**：视图、分页、分支切换等用查询参数
3. **右键菜单 = 操作入口**：所有功能入口统一在右键菜单
4. **预加载优先**：常用数据预加载，减少等待时间
5. **不向后兼容**：旧路径格式废弃，显示错误提示

## 二、路径结构

### 2.1 改造后路径体系

| 层级 | 路径格式 | 说明 |
|-----|---------|------|
| 根目录 | `github:///` | 显示我的仓库列表 |
| 仓库根目录 | `github:///repo/` | 只显示真实文件 |
| 仓库子目录 | `github:///repo/src/` | 只显示真实文件，继承 `?ref=` |
| 视图 | `github:///repo/?view=issues` | Issues/Pulls/Branches 等 |
| 搜索 | `github:///?search=repos&q=react` | 搜索仓库 |
| 分页 | `github:///?page=2` | 翻页（Issues/Pulls/搜索） |
| 分支切换 | `github:///repo/src/?ref=develop` | 切换分支/标签 |
| owner 消歧 | `github:///vscode/?owner=microsoft` | 同名仓库区分 |

### 2.2 路径示例

```
根目录：
github:///
├── react/                    ← 我的仓库
├── vscode/
├── angular/
└── ...

仓库根目录：
github:///react/
├── src/                      ← 真实文件
├── docs/
└── README.md

仓库子目录（继承分支）：
github:///react/src/?ref=develop
├── components/
├── hooks/
└── index.tsx

视图（Issues）：
github:///react/?view=issues&page=2
├── #1 Bug in render
├── #2 Feature request
└── ...

搜索结果：
github:///?search=repos&q=react&page=1
├── facebook/react/           ← 双击跳转 github:///react/?owner=facebook
├── vuejs/vue/
└── ...
```

## 三、参数体系

### 3.1 参数定义

| 参数 | 值域 | 用途 | 示例 |
|-----|------|------|------|
| `view` | starred, watched, notifications, gists, trending, issues, pulls, branches, tags, releases | 视图类型 | `?view=issues` |
| `search` | repos, code, users, issues, commits, topics | 搜索类型 | `?search=repos` |
| `q` | 任意字符串 | 搜索关键词 | `?q=react` |
| `ref` | 任意字符串 | 分支/标签/SHA | `?ref=develop` |
| `owner` | 任意字符串 | owner 消歧 | `?owner=microsoft` |
| `page` | 正整数 | 分页页码 | `?page=2` |
| `state` | open, closed, all | Issues/Pulls 状态 | `?state=open` |
| `since` | daily, weekly, monthly | Trending 时间范围 | `?since=daily` |
| `lang` | 任意字符串 | Trending/搜索语言 | `?lang=javascript` |
| `from` | search | 来源标记（返回搜索） | `?from=search` |

### 3.2 参数组合

```
?view=issues&state=open&page=2              ← Issues（打开状态，第2页）
?view=pulls&state=closed                    ← PRs（已关闭）
?view=branches                              ← 分支列表（不分页）
?view=trending&since=daily&lang=python      ← Python 今日趋势
?search=repos&q=react+language:js&page=2    ← 搜索仓库（第2页）
?ref=develop&page=2                         ← develop 分支（如需分页）
```

### 3.3 参数继承规则

| 场景 | 继承规则 |
|-----|---------|
| 进入子目录 | 继承父目录的 `?ref=` 参数 |
| 进入视图 | 不继承 `?ref=`（视图与分支无关） |
| 进入搜索结果 | 添加 `?owner=` 和 `?from=search` |

## 四、右键菜单设计

### 4.0 Verb 命名规范（重要）

**DOpus 自定义菜单命令处理机制**：

1. **菜单定义**：使用 `$gh_xxx` 格式（带 `$` 符号）
   - `$` 符号用于标识这是插件自定义命令，与 DOpus 内置命令区分
   - 例如：`L"$gh_view_issues"`

2. **Verb 匹配**：使用 `gh_xxx` 格式（不带 `$` 符号）
   - DOpus 在调用 `VFS_ContextVerbW` 时会自动去掉 `$` 符号
   - 插件匹配时必须使用不带 `$` 的版本
   - 例如：`_wcsicmp(lpVerbData->lpszVerb, L"gh_view_issues") == 0`

3. **命名规范**：
   - 所有自定义命令以 `gh_` 开头（GitHub 插件标识）
   - 内置命令直接使用 DOpus 标准名称（如 `Clipboard COPY`、`Delete`、`Rename`）

**代码示例**：
```cpp
// 菜单定义（VFS_GetContextMenuW）
item = { sizeof(VFSCONTEXTMENUITEMW), 0, L"查看 Issues(&I)", L"$gh_view_issues" };

// Verb 匹配（VFS_ContextVerbW）
if (_wcsicmp(lpVerbData->lpszVerb, L"gh_view_issues") == 0) {
    // 处理逻辑...
}
```

```cpp
    std::wstring resolvedOwner;     // 解析后的 owner（从缓存或参数）
```

### 7.4 ReadSearchDirectory 实现

```cpp
static int ReadSearchDirectory(LPVFSREADDIRDATAW lpRDD, const GitHubPathInfo& pathInfo) {
    const std::wstring& type = pathInfo.query.search;
    const std::wstring& q    = pathInfo.query.query;
    int page                 = pathInfo.query.page;
    
    if (type == L"repos")   return SearchRepos(lpRDD, q, page);
    if (type == L"code")    return SearchCode(lpRDD, q, page);
    if (type == L"users")   return SearchUsers(lpRDD, q, page);
    if (type == L"issues")  return SearchIssues(lpRDD, q, page);
    if (type == L"commits") return SearchCommits(lpRDD, q, page);
    if (type == L"topics")  return SearchTopics(lpRDD, q, page);
    
    return AddErrorFile(lpRDD, L"⚠ 未知搜索类型.txt", L"不支持的 search 参数: " + type);
}
```

## 八、预加载与缓存策略

### 8.1 预加载策略

| 数据类型 | 预加载时机 | 缓存策略 |
|---------|-----------|---------|
| 我的仓库 | 插件初始化时 | 预加载 + 缓存（超时可配置） |
| 星标仓库 | 首次访问时 | 懒加载 + 缓存 |
| 关注仓库 | 首次访问时 | 懒加载 + 缓存 |
| 仓库文件 | 进入仓库时 | 懒加载 + 缓存 |
| Issues/Pulls | 首次访问时 | 懒加载 + 分页缓存 |

### 8.2 加载状态处理

```cpp

        StartPreloadRepos();
        
        return TRUE;

    // 预加载完成，显示仓库列表
    std::vector<GitHubRepoInfo> repos = g_cachedRepos.Get();
    // ... 渲染仓库列表
}
```

### 8.3 缓存刷新策略

## 九、分页策略

### 9.1 分页需求分析

| 场景 | 是否分页 | 原因 |
|-----|---------|------|
| 我的仓库 | ❌ 不分页 | 预加载全部，数量可控 |
| 星标仓库 | ❌ 不分页 | 数量通常可控 |
| Issues | ✅ 分页 | 可能很多，API 限制 |
| Pulls | ✅ 分页 | 可能很多 |
| Branches | ❌ 不分页 | 通常 < 100，一次性加载 |
| Tags | ❌ 不分页 | 通常 < 100 |
| Releases | ❌ 不分页 | 通常 < 100 |

## 十二、搜索历史

### 12.1 搜索历史存储

```cpp
// 搜索历史结构
struct SearchHistoryEntry {
    std::wstring type;     // repos, code, users, issues
    std::wstring query;    // 搜索关键词
    time_t timestamp;      // 搜索时间
};

// 全局搜索历史（最多保存 5 条）
static std::vector<SearchHistoryEntry> g_searchHistory;

// 添加搜索历史
static void AddSearchHistory(const std::wstring& type, const std::wstring& query) {
    SearchHistoryEntry entry = { type, query, time(nullptr) };
    
    // 检查是否已存在相同搜索
    for (auto it = g_searchHistory.begin(); it != g_searchHistory.end(); ++it) {
        if (it->type == type && it->query == query) {
            g_searchHistory.erase(it);
            break;
        }
    }
    
    g_searchHistory.insert(g_searchHistory.begin(), entry);
    
    // 保持最多 5 条
    if (g_searchHistory.size() > 5) {
        g_searchHistory.resize(5);
    }
}
```
